Decision status colors

These three colors carry a single, fixed meaning everywhere in the portfolio: the GO / CONDITIONAL / NO-GO decision on a use case. They are deepened from the source template's dark-theme values for AA contrast on a white surface, but keep the same universal green/amber/red convention — never reused for anything else.
--green / --ok
#1e8449

--warn
#a6720d

--err
#c22b35

Rule: when re-skinning for a new client, the accent hues (gold/bronze/mocha/terracotta above) may change freely to match the new brand. The GO/CONDITIONAL/NO-GO status colors should stay a recognizable green/amber/red so the decision funnel, chips and phase indicators read correctly at a glance across every client deployment.
Typography

One typeface family

The source template pairs IBM Plex Sans (body) with IBM Plex Mono (uppercase labels). Chanel.com uses no public web font — nav and body both run on a Helvetica Neue / Helvetica / Arial fallback stack — so both roles are mapped to the same Helvetica stack here, with the "mono" role kept visually distinct only via uppercase + letter-spacing, matching Chanel's own nav treatment.

Reuse for the next client

How to re-skin this portfolio

1. Copy brands/chanel.json to brands/<client>.json and replace the surface/text/accent hex values with the new client's palette (surfaces from their site background/panels, text from their body/nav copy color, one or two accents from their brand or product photography).

2. Run python3 scripts/apply_brand.py --brand brands/<client>.json --in-dir raw_exports/ --out-dir domains/ against that client's Process Studio dashboard exports.

3. Re-extract the shared stylesheet (the script re-skins each file's embedded <style> block the same way regardless of whether it's inline or linked) and rebuild index.html's combined-portfolio numbers from the new client's portfolio_synthesis.json files per domain.

No template HTML, CSS class name, or JavaScript function needs to change — only the brand config and the per-domain data.
