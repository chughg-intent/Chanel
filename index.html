Every GO is a business case, not a suggestion →

Each of the 520 use cases below was scored for automation feasibility, then costed: implementation effort, annual savings, payback period, and the specific risks and success factors that determine whether it ships. A GO decision clears both an automation-feasibility bar and a technical-feasibility bar with no regulatory blocker; CONDITIONAL use cases are held back by a named, resolvable dependency — a tool not yet live, a governance sign-off pending — not by weak economics.

Methodology

How this portfolio was built

Process Studio reads each SOP document directly rather than working from a summary of it — extracting the process steps, systems, roles, decision points and stated pain points, then generating candidate automation use cases against that process rather than a generic library of automation ideas. Where a domain has more than one SOP, the same use cases are then compared pairwise and holistically across documents to surface duplicated tasks, conflicting instructions, and automation opportunities that only become visible once the whole domain is read together.

Each domain (FP&A, O2C, R2R, S2P) was analysed independently against Chanel's own SOP documentation for four constituent processes per domain. Every use case was scored for automation feasibility and given a GO / CONDITIONAL / NO-GO decision, then rolled into a per-domain portfolio synthesis: cross-SOP automation opportunities and task consolidation, a phased implementation roadmap, the automation-approach mix, and a portfolio-level risk register.

All financial figures are benchmark-based: role-tier fully-loaded hourly rates applied to volumes stated in each SOP where available, and to grounded estimates elsewhere. Savings totals include only GO use cases; CONDITIONAL use cases (18 across the portfolio) are excluded from totals pending unblocking dependencies (e.g. tooling not yet live, shared ML platform, Responsible AI approval) and are sequenced into later phases. This combined view sums each domain's own independently-computed economics — it does not assume cross-domain platform sharing beyond what each domain already recommends internally.

Every automation in every domain keeps a human in the loop for payment, approval, master-data and accounting-judgment decisions — no use case proposes autonomous financial action.
